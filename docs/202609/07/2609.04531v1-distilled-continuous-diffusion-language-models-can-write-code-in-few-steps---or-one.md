## 摘要
语言生成几乎被普遍视为一个序列化过程：自回归模型一次生成一个 token，而扩散语言模型则用长轨迹的迭代细化取代了 token 级别的串行性。在这项工作中，我们引入了用于代码生成的 0.7B 连续扩散语言模型 PlaidQ，并展示了其轨迹可以被激进地蒸馏为仅需少量去噪步骤——甚至仅需一步，从而实现高效的代码生成。PlaidQ 将预训练的自回归模型重新用作连续 token 嵌入上的双向去噪器。我们通过分布匹配对 PlaidQ 进行少步生成蒸馏，并通过配对轨迹监督进行单步生成蒸馏。在模型规模相当的情况下，PlaidQ 在代码生成任务上与离散扩散语言模型具有竞争力。蒸馏过程改变了质量与计算的边界：16 步的学生模型在 HumanEval 和 MBPP+ 上分别达到了 31.78 和 40.49 的 pass@10，超过了采样 512 步的同款 PlaidQ 教师模型。在极端情况下，配对轨迹蒸馏在单步去噪下于 HumanEval 上实现了 7.07 的 pass@1，能够生成功能正确的程序。总之，这些结果确立了连续扩散作为实现少步和单步代码生成的可行路径。从更广泛的角度来看，连续扩散不仅仅是语言的另一种表示形式：它提供了一个接口，使语言模型能够继承连续扩散建模的加速和蒸馏机制。训练与推理代码及模型检查点可在 https://github.com/pengzhangzhi/plaidq 获取。

## Abstract
Language generation is almost universally treated as a sequential process: autoregressive models emit one token at a time, while diffusion language models replace token-level seriality with a long trajectory of iterative refinement. In this work, we introduce PlaidQ, a 0.7B continuous diffusion language model for code generation, and show that its trajectory can be aggressively distilled into only a few denoising steps---or even one, enabling efficient code generation. PlaidQ repurposes a pretrained autoregressive model as a bidirectional denoiser over continuous token embeddings. We distill PlaidQ with distribution matching for few-step generation and paired-trajectory supervision for one-step generation. At matched model scale, PlaidQ is competitive with discrete diffusion language models on code generation. Distillation then shifts the quality--compute frontier: a 16-step student reaches 31.78 and 40.49 pass@10 on HumanEval and MBPP+, surpassing the same PlaidQ teacher sampled for 512 steps. At the extreme, paired-trajectory distillation achieves 7.07 pass@1 on HumanEval with a single denoising step, producing functionally correct programs. Together, these results establish continuous diffusion as a viable path to few-step and one-step code generation. Broadly, continuous diffusion is not merely another representation for language: it provides an interface through which language models can inherit the acceleration and distillation machinery of continuous diffusion modeling. Training and inference code and model checkpoints are available at https://github.com/pengzhangzhi/plaidq.

### 1. 核心问题与研究动机（Motivation & Background）

* **研究背景**：
  * **自回归模型（AR）**：逐 token 生成（Seriality），存在严格的串行依赖，导致推理延迟高，长文本/代码生成受到严重瓶颈限制。
  * **离散/连续扩散语言模型（DLMs）**：支持并行去噪更新全序列，但通常需要几十到数百步（如 128~512 步）的漫长去噪轨迹，只是将瓶颈从“token 级别的串行”转移到了“去噪步骤（轨迹）的串行”。
  * **连续扩散模型的潜力与局限**：大部分连续空间扩散模型仅在无条件文本生成和困惑度（Perplexity）指标上进行评估，容易倾向于低熵重复输出，未能验证序列级别的功能正确性（如代码执行）。
* **核心问题**：
  * **连续扩散语言模型能否在极少数步骤（4-16步）甚至仅仅一步（1-step）去噪内生成功能正确、可执行的代码？**

### 2. 方法论（Methodology）

#### (1) 基础模型构建：PlaidQ
* **架构复用与对齐（AR-to-Diffusion Transition）**：基于 0.6B 参数的 Qwen3 架构，将其重构为连续 token 嵌入（Embedding）空间上的双向去噪器（0.7B 参数）。复用预训练 Transformer 主干与词表投影矩阵 $W$，将因果注意力替换为双向注意力。
* **输出头错位对齐（Head Alignment）**：为了保留 AR 模型的预测能力，PlaidQ 预测 $p_\theta(y_i | x_t, t) = \text{softmax}(h_{i-1} W^\top)$，将输出头位置向前偏移一位，保留预训练表示几何。
* **SWVR 算子（高效分类重参数化）**：
  * 连续扩散在计算期望嵌入 $\hat{x}_\theta^0 = \text{softmax}(h W^\top) E$ 时，面对 152k 大词表会产生巨大的 $[B, L, V]$ 显存瓶颈。
  * 设计了 **SWVR（Softmax-Weighted Value Readout）** 融合算子，借鉴 FlashAttention 思想，采用分块在线流式（Streaming）计算 log-partition 和代码本期望 $pE$，**无需显式展开全词表概率张量**。

#### (2) 优化与加速策略
* **混合优化器（Hybrid Muon–AdamW）**： Transformer 主干的 2D 权重矩阵使用 Muon 优化器更新，嵌入层、归一化、偏置及词表头保留 AdamW 优化器。

#### (3) 轨迹蒸馏技术（Trajectory Distillation）
* **少步生成：分布匹配蒸馏（DMD / DMD2 范式）**：
  * 用于蒸馏出 **PlaidQ-D4、PlaidQ-D8、PlaidQ-D16** 学生模型。
  * 学生模型仅保留其中一步去噪的梯度（rollout 轨迹），将生成结果重新加噪后，由冻结的教师模型（Teacher）和可训练的 Critic 模型评估，利用两者分数的差异梯度更新学生模型，消除训练与推理间的分布偏移。
* **极端单步生成：配对轨迹蒸馏（Paired Trajectory Distillation）**：
  * DMD 在 1 步时效果有限，因此对 **PlaidQ-D1** 采用配对监督。
  * 强制单步学生模型与多步教师模型从**相同的初始高斯噪声 $z$** 出发，直接以教师生成的完整序列作为 pointwise 交叉熵监督目标，让学生建立从特定噪声到完整正确代码的映射。
* **步骤相关的步长温度控制（Step-dependent Score Temperature）**：随着去噪步数激减，推导了维持 DDIM 采样更新稳定的反向映射增益条件 $\rho_K(\tau) < 1$，为不同步数的学生模型动态匹配步长温度 $\tau(K)$。

### 6. 主要结论与发现（Main Findings）

1. **连续扩散在代码生成上具备竞争力**：在 128 步采样下，0.7B 的 PlaidQ 在 HumanEval+ 上达到 18.05 pass@1，超越同规模离散扩散模型 Open-dCoder (17.6) 和 oDLM (16.4)。
2. **蒸馏改变了质量与计算边界（以少胜多）**：
   * **16 步蒸馏模型（PlaidQ-D16）** 在 HumanEval 和 MBPP+ 上分别实现 **31.78** 和 **40.49** 的 pass@10，**超越了采样 512 步的 PlaidQ 教师模型**（28.57 / 35.21），实现了 8x~32x 的加速。
   * **8 步模型（PlaidQ-D8）** 保留了教师模型 128 步时 90%~98% 的性能。
   * **4 步模型（PlaidQ-D4）** pass@10 相较未经蒸馏的 4 步采样提升了 2~4 倍（HumanEval: 7.90 -> 15.85; MBPP+: 7.91 -> 30.94）。
3. **单步去噪可生成可执行代码**：配对轨迹蒸馏获得的 **PlaidQ-D1** 模型在 HumanEval 上实现了 **7.07 pass@1**，首次证明连续扩散语言模型仅需**单步去噪**即可生成功能正确、可执行的完整程序。
4. **零样本代码填充能力**：仅在前缀补全上训练的 PlaidQ 能零样本迁移至代码 Fill-in-the-Middle 任务，在 HumanEval-Infill 上取得 37.91 分，优于 Open-dCoder (32.5)。
5. **消融有效性**：AR 初始化使验证 NLL 从 3.65 降至 3.59；SWVR 算子减少了 **29.6%** 的峰值激活显存；Muon 优化器收敛损失显著优于纯 AdamW。

### 7. 优点与亮点（Strengths）

* **架构与算子创新**：SWVR 算子巧妙解决了大词表连续扩散语言模型的显存爆炸难题，使连续扩散训练更加高效。
* **打破扩散模型推理慢的魔咒**：通过 DMD 分布匹配与配对轨迹蒸馏，成功将连续扩散模型的推理步数压缩至 16 步以内，且质量**反超**多步教师模型。
* **首创性结论**：首次成功实现单步去噪（1-step continuous diffusion）下的功能性代码生成。
* **灵活的双向上下文能力**：无需专门的 FIM 训练，天然具备出色的零样本代码中插/填充能力。

### 8. 不足与局限（Limitations）

* **模型参数规模受限**：目前验证仅停留在 0.7B（基于 Qwen3-0.6B）小模型级别，尚未在大规模模型（7B+ / 70B+）上验证连续蒸馏的扩展规律（Scaling Laws）。
* **单步生成的绝对性能仍有提升空间**：单步模型 PlaidQ-D1 的 pass@1（7.07%）虽然具备里程碑意义，但离实际工业化部署的高精度需求仍有差距。
* **算子与硬件细节隐去**：未公开使用的 GPU 类型与具体数量，难以精确评估训练的实际算力开销（FLOPs）。
* **MBPP+ 测试集评估范围**：MBPP+ 的测试使用的是任务集自带的 Base 断言，而非完整的 EvalPlus 拓展测试集，在严格比对时需注意这一前提。
* **CFG 开销**：无分类器引导（CFG）虽然效果显著，但会将每步的网络前向传播次数（NFE）翻倍（2K+1），且负向分支的前缀加噪策略属于启发式设计。
